# Roadmap

This file tracks current project work and release readiness.

## Current Focus

`zig-vst3` is the raw VST3 API package. `zig-vst3-plugin` is the higher-level plugin framework package. Both are now exercised by validator-passing example bundles and the public CI matrix.

Near-term work should stay focused on finishing release confidence before adding broad new features:

- Keep the Zig version pinned in `docs/toolchain.md` and CI. Update it only through a dedicated PR.
- Keep the VST3 SDK version pinned in `scripts/fetch_sdk.*` and documented in `docs/toolchain.md`.
- Keep host smoke results in `docs/host-matrix.md`.
- Keep public API docs synchronized with framework changes.

The 2026-07-30 expanded HRTF gate supersedes the synthesis gap above. A fixed-capacity measured-response database validates head-relative full-sphere directions, stereo impulses, and fractional per-ear delays. Allocator-owned checked dynamic matrices and the Legendre, Chebyshev, Hermite, Laguerre, and Jacobi polynomial families are also implemented.

The DirectSpeakers path now performs Cartesian screen-edge transformation internally. It uses the specified five-sector position conversion, elevation mapping, polar-domain edge substitution, and upper-front layout compensation before passing the nominal point to bounds matching or the Cartesian point-source panner. A caller-computed transformed position remains available only as an explicit override.

The polar point-source renderer triangulates nominal speaker positions and evaluates regions at measured reproduction positions. It supports triplet and quadrilateral regions, virtual upper and lower speakers with direct downmix, virtual pole downmix, and the dedicated stereo path. DirectSpeakers can invoke either polar or Cartesian fallback through one checked mixer.

Polar Objects extent now uses a fixed 1,652-direction spreading grid with caller-owned precomputed gains. It applies the rounded polar weighting shape, the specified edge fade and small-extent transition, distance-dependent apparent size, depth endpoints, divergence, and the existing Objects transforms before producing direct and diffuse gain vectors.

Cartesian Objects extent uses separable 40-point virtual-source axes, with a 20-point nonnegative height axis for layouts below three height planes. It applies the specified extent scaling, dimensional exponent, inside and boundary contributions, room-boundary fade, and point transition before composing divergence and direct/diffuse gain vectors.

Objects zone exclusion is retained as bounded typed polar or Cartesian metadata. Polar point and extent rendering select excluded speakers from nominal positions and redistribute their gain power through tolerance-grouped layer, front/back, and distance priorities. Cartesian rendering repairs affected allocentric rows, omits excluded speakers from channel lock and panning, and maps the reduced-layout result back to the complete output order.

Timed Objects rendering now precomputes a caller-bounded sequence of point or extent gain targets. Exact rational block times drive sample coverage and ordinary, immediate-jump, or shortened gain interpolation across arbitrary processing partitions. First blocks, gaps, zero-duration state blocks, direct and diffuse targets, and changing exclusion behavior are covered.

Objects diffuse processing uses one deterministic 512-sample random-phase all-pass FIR per canonical output label and a 255-sample direct-path delay. The processor owns caller-bounded coefficient and history storage, is invariant to layout ordering, accepts arbitrary block partitions, and composes after static or timed direct and diffuse gain buses.

DirectSpeakers rendering now applies the complete ordered common-layout mapping table before ordinary exact-label, bounded-position, LFE, and point-panner fallback. The mapping recognizes the supported common input packs, mirrors lateral rules, enforces input and output layout restrictions, requires every destination label, composes block gain into allocation-free multi-output mixing, and falls through without changing the existing route when no rule is complete.

`AdmMatrixCoefficientMixer(Sample, maximum_delay_samples)` retains the standards-conformant constant-gain and rounded-delay path. `AdmVariableMatrixCoefficientMixer(Sample, maximum_delay_samples, maximum_variables, maximum_points, maximum_phase_taps)` adds an explicit product-policy path for named gain, phase, and delay variables. Caller-bounded absolute-sample lanes use held or linear interpolation. Delay endpoints follow the nearest-sample rule and interpolate fractionally between endpoints. An antisymmetric caller FIR supplies the quadrature path for phase rotation, adds its integer group delay to every term, and makes bandwidth, ripple, and latency policy explicit. Both paths are allocation-free, contain non-finite input, validate before mutation, and remain identical across arbitrary host partitions.

`AdmHoaMatrixDecoder(Sample, maximum_inputs, maximum_outputs)` validates ordered HOA component sets and applies caller-supplied output-major decode matrices. It supports f32 and f64, orders through 50, N3D, SN3D, and FuMa through order three, static block gain, arbitrary component ordering, non-finite input containment, and transactional replacing output. `AdmHoaLoudspeakerMatrix(Sample, maximum_inputs, maximum_outputs)` now derives compatible matrices for arbitrary full-rank loudspeaker layouts. It exposes the real basis evaluator, uses a checked SVD pseudoinverse, reports conditioning, supports basic and max-rE order weights, leaves LFE outputs silent, and rejects component mismatches when constructing the decoder.

`AdmBinauralStereoMixer(Sample)` directly renders one static already-binaural block per ear. `AdmBinauralStereoGainTimeline(Sample, maximum_blocks_per_ear)` retains two independently timed ear-channel sequences and renders absolute sample ranges. Exact rational timing supports ordinary interpolation, immediate or shortened jump transitions, silent gaps, and arbitrary host partitions without allocation. Both types accept current and legacy ear names, map either input order, and apply linear or dB gain. `HrtfDatabase`, `HrtfRenderer`, `HrtfMotionRenderer`, and `HrtfSofaLoader` provide the separate measured-response path from standard datasets through static or scheduled mono-to-stereo rendering.

Polyphase IIR oversampling additionally supports bounded runtime construction from zero through eight independently specified stages for single-channel or multichannel processing. Reconfiguration is transactional between blocks and preserves the fractional or exact-integer latency contract.

Mixed oversampling lists can combine automatically sized and response-verified equiripple FIR stages, polyphase IIR stages, and no-op dummy stages. Every real stage accepts separate upsampling and downsampling specifications.

Vorbis positional-file seeking uses caller-owned indexes, safe overlap-prime packet locations, transactional reader repositioning, and exact decode-forward PCM trimming. The first indexed page retains a stream-start anchor for targets inside packed pages, while later points retain shorter overlap-prime anchors. The chained PCM decoder resets only after EOS, requires stable channel, block, and sample-rate geometry, and reports checked continuous positions across logical streams. ## Validation Tiers

- Tier 0: `zig build` and `zig build test`.
- Tier 1: `zig build raw-api-abi`.
- Tier 2: `zig build validator` and `zig build validate-examples` on platforms where Steinberg validator support is available.
- Tier 2 optional: `zig build pluginval-examples` and `zig build pluginval-strict-examples` when Tracktion pluginval is installed.
- Tier 3: real host smoke tests recorded in `docs/host-matrix.md`.

For normal code changes, run the smallest tier that covers the changed behavior. For release work, use `scripts/raw_api_release_check.sh` and the checklist in `docs/release-checklist.md`.

## Framework API Symmetry

The current `zig-vst3-plugin` public surface has had a symmetry pass across `process.zig`, `parameters.zig`, `state.zig`, `units.zig`, and `plugin.zig`.

Current interpretation:

- `ParameterSet`, `ParameterView`, and `ParameterEditor` share the same metadata, validation, conversion, and reflected parameter-change construction surface. `ParameterEditor` adds mutation, reset, copy, and process-change application methods.
- `PluginInstance` exposes the practical instance-bound parameter, unit, program-list, program, state, lifecycle, topology, process, and metadata helpers without forwarding every value-level helper as an alias.
- `ProcessorRuntime` owns format-neutral prepare, activation, processing, flush, state-restore, latency, tail, reset, release, and teardown ordering. `OfflineRenderer`, `StandaloneRuntime`, `Vst3Processor`, the LV2 `CoreAdapter`, and the Audio Unit render core consume the same lifecycle. The Audio Unit render core covers negotiated sample rate and block size, initialize and uninitialize, f32 and f64 deinterleaved processing, static main and auxiliary buses, process attachments, deterministic failure silence, and statistics. SDK-checked AUv2 declarations and dispatch cover lifecycle, static bus and planar stream properties, maximum frames, latency, tail, input pull callbacks, reflected parameter metadata, immediate get and set, bounded sample-offset point and ramp automation, Core Foundation class-info state, bounded property listeners, pre-render and post-render notifications, and allocation-free multi-output rendering. Ramps use a shared process attachment with signed starts, linear interpolation, deterministic event precedence, and next-block boundary persistence. A timestamp-keyed fixed-storage cache supports main-first, auxiliary-first, and repeated output-bus requests with one processor execution and one automation application per block. Owning component factories, registered Mono Gain and Auxiliary Output Splitter `.component` bundles, plist and symbol validation, dynamic-library host fixtures, and cross-target component builds are implemented. External AU host validation remains. The LV2 core adapter covers static f32 audio and control ports, bounded Atom Sequences, segmented transport, typed Patch Set and Get properties, block-size options, optional output port resizing during processing, declaration-driven freewheeling mode, latency, parameter and component state, bounded Worker scheduling, and Programs enumeration and selection. Dynamic fixtures cover Patch timing and hostile messages, output resize requests, immediate offline and delayed threaded Worker delivery, response lifetime, end-of-cycle ordering, simultaneous UI instances, and repeated UI close and reopen lifecycles. The LV2 UI adapter bridges the toolkit-neutral editor to parent attachment, construction and runtime host scale options, controls, Programs selection, idle, resize, show, hide, and teardown. The VSTGUI backend supplies a linked parameter editor and native widget. Generated metadata covers ports, Patch access, presets, Programs, optional resize support, and the separate UI resource. Independent schema validation and warning-fatal direct-distribution lint pass. External-host validation, advanced custom components, remaining extensions, and dynamic topology remain.
- `StandaloneRuntime` maps checked realtime device blocks into the processor runtime. `DeviceChannelRouter` maps flat physical channels onto main and auxiliary buses with fixed storage and whole-device failure silence. `Midi1BlockScheduler` and `UmpBlockScheduler` bridge one device producer to one audio-thread consumer, convert absolute timestamps to sample offsets, retain future and capacity-limited packets, and count rejected callback packets. The UMP path preserves all four packet widths without narrowing non-event messages. `StandaloneApplication` coordinates transactional audio-device and processor lifecycle. Audio callback, timestamped MIDI 1 and UMP device, deterministic failure silence, callback-failure, bounded discovery catalog, deterministic selection fallback, versioned selection persistence, and transactional recovery contracts are format neutral. `DeviceRecoveryController` commits only successful fallback or restart operations, retries failures, and restores a returning preferred device. A bounded multi-source monitor connects retained CoreAudio, WASAPI, ALSA PCM, PipeWire, CoreMIDI, WinMM, ALSA MIDI 1, ALSA UMP, and Windows MIDI Services failures to same-selection recovery without consuming partial observations. CoreAudio keeps processor callback rejection separate from device-side failures. `StandaloneWindow` and `StandaloneShell` add top-level native-parent ownership, bounded window events, visibility, resize, scale, focus, quit ordering, failure polling, and recovery application. Versioned selection distinguishes unified devices from independent capture and render endpoints. Optional modules provide CoreAudio, CoreMIDI, and an AppKit top-level window on macOS, event-driven shared-mode WASAPI, timestamp-scheduled WinMM MIDI 1, native complete UMP through the MIDI Services App SDK, and a Win32 top-level window on Windows, and runtime-loaded ALSA PCM and PipeWire audio, timestamp-scheduled MIDI 1 and UMP RawMIDI, X11, and Wayland windows on Linux. The scheduled native MIDI backends use fixed-capacity queues, stable ordering, nonblocking admission, cancellation on replacement or close, and retained output statistics. A shared VST3 bridge supplies the Wayland host, frame, native objects, resize path, and delegated run loop. The bounded Steinberg run-loop driver supplies file-descriptor and timer integration for both VSTGUI Linux paths. Sustained cross-device drift compensation, physical PipeWire, scheduler and recovery confirmation, and physical window integration remain.
- `UnitSet` retains the broad program metadata lookup surface. `PluginInstance` forwards the host-facing and instance-useful paths, especially list-id, list-name, unit-id, and unit-name program metadata paths.
- `ProcessContext` provides direct input, output, parameter-change, input-event, output-event, timing, segment, and writer helpers. The current distinction between input events, output events, and generic event views is intentional.
- `state` value types provide direct report/header helpers, while `PluginInstance` binds the helpers that need the reflected parameter count.

The standalone lifecycle fixture now covers a callback during stop, stale callbacks after stop and failed startup, processor rollback, clean restart, and successful retry. Physical callback timing and recovery remain external checks.

Do not add aliases only to make every type expose every spelling. Add new API only when a real workflow needs the helper at that API boundary.

## Non-goals

- Hosting plugins. This project builds plugins, not hosts.
- VST2 compatibility.
- A mandatory GUI toolkit. VSTGUI is an optional reference adapter, and users can provide another toolkit.
- Plugin sandboxing or out-of-process hosting.
