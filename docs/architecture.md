# Architecture

The project has two packages:

- `zig-vst3`: raw Zig bindings for the VST3 COM API
- `zig-vst3-plugin`: a higher-level framework built on top of `zig-vst3`

The raw API owns ABI compatibility, TUID/FUID handling, vtable layout, factory exports, and bundle entry points. The plugin framework owns the user-facing plugin interface, parameters, state, automation, MIDI/event handling, and examples. Its bounded audio topology exposes 39 non-empty VST3 layouts across stereo roles, cinematic and music surround, immersive 5.x and 7.x sets, and first- through seventh-order ACN ambisonics. Version-2 topology state expands supported-layout masks to 64 bits while restoring version-1 masks with unchanged layout identifiers.

The high-level processor path has three layers:

- `PluginInstance(Plugin)` owns the declared plugin, reflected parameters, metadata, and state helpers.
- `ProcessorRuntime(Plugin)` adds the format-neutral lifecycle state machine and checked processing boundary.
- `audio_unit.RenderAdapter` supplies negotiated Audio Unit render semantics over that runtime. `audio_unit_v2` adds SDK-checked declarations plus lifecycle, property, parameter, input-pull, sample-offset automation, multi-output render dispatch, Core Foundation class-info state, and an owning component factory. The Mono Gain reference builds as a registered macOS `.component` bundle and passes a dynamic-library host fixture that saves, mutates, and restores parameter state. External-host validation remains under development.
- Format consumers translate their own buffers, events, transport, state storage, and lifecycle callbacks into the runtime contract.

`OfflineRenderer` is the first non-VST3 consumer. It partitions a complete render into bounded offline blocks, rebases automation and events, advances transport positions, and combines emitted events into the caller's timeline. It has no dependency on VST3 interfaces.

`StandaloneRuntime` is the live non-VST3 consumer. It maps checked audio-device blocks, MIDI-derived events, automation, output events, and transport into the same runtime. `DeviceChannelRouter` translates flat physical channels into main and auxiliary bus views without allocation, supports repeated or silent input routes, requires distinct output routes, and clears unmapped or failed device outputs. A bounded single-producer, single-consumer queue maps absolute MIDI timestamps into sample offsets while retaining future or capacity-limited packets. `StandaloneApplication` owns transactional audio-device and processor lifecycle. A bounded, generation-tracked control-thread catalog supplies stable audio and MIDI identifiers, deterministic fallback selection, and versioned selection persistence. `DeviceRecoveryController` applies fallback, retry, preferred-device restoration, and explicit restart requests transactionally on the control thread. A bounded failure-monitor set combines monotonic native audio and MIDI failure counters without consuming partial observations when one source read fails. `StandaloneWindow` owns a native top-level parent around the shared editor contract. `StandaloneShell` pumps bounded window events, requests recovery for new backend failures, and applies recovery before the next control cycle. Platform backends implement enumeration, device I/O, and native windows without entering the processor package.

`Vst3Processor(Plugin)` adapts the same runtime to the reusable VST3 `SimpleEffect` shell. The shell owns VST3 parameter serialization and bus topology, while the adapter owns the high-level plugin instance and lifecycle. Parameter flushes, audio blocks, and component-state restores synchronize the two parameter stores. Optional resource-path and decoded-audio receivers, scalar, graph, and text telemetry, editor visibility notifications, bounded component payloads, connection readiness, and all twelve typed VST3 restart categories pass through the adapter. Host requests coalesce until a non-realtime dispatch succeeds. Unsupported sample precision and runtime process failures are reported to the host.

`lv2.CoreAdapter(Plugin, plugin_uri, maximum_block_size)` exposes a static f32 declaration through the LV2 core ABI. It flattens main and auxiliary audio buses into ports, maps reflected parameters to plain-unit control inputs, translates representable Atom Sequence MIDI channel messages into typed events, and preserves complete raw MIDI plus arbitrary bounded non-MIDI Atom bodies as typed data events in both directions. Time Position objects segment processing at their sample offsets. Input and emitted events are rebased for each segment and restored to block-relative offsets at the port boundary. The adapter applies instantiation-time minimum, maximum, and nominal block-length options, exposes those values through the Options interface, reports latency through a control output, and exposes parameter plus bounded component persistence through the LV2 State interface when the host supplies URID mapping. Plugins may opt into the Worker extension through bounded request and response hooks. Scheduling is restricted to `run`; work executes in the host's non-realtime context, and responses return through `run`. The host maximum may narrow but cannot exceed the adapter's compile-time bound. While inactive, Options `set` can reprepare the processor with a new valid maximum and atomically publish the matching bounds. Component bytes use a separate portable property and share the framework's component-state hooks with VST3. Construction, cleanup, state operations, inactive reconfiguration, and worker execution may allocate or use bounded stack storage, while connection, schedule, response, and run callbacks do not. Malformed MIDI, malformed options, state payloads, worker bodies, or oversized runs fail deterministically, and run failures clear every connected audio and event output.

The ARA layer translates the pinned official ARA API header for each target and keeps the VST3 companion interfaces in Zig with an exact C++ layout and vtable-slot check. `ara_factory.Factory` owns a fixed controller pool and optional controller extension state. Each `ara_document_controller.Controller` exposes the versioned C callback table over `ara_model.Document`, which enforces editing transactions, generational references, persistent identifiers, graph ownership, sample-access state, and destruction order. A bounded generational reader pool permits concurrent non-realtime readers for one source. Each read takes an atomic slot lease, and synchronous source-access disable waits for every lease before destroying the host readers. Readers use bounded planar pointer staging and also close before the controller is released. Product code may attach a typed content provider for notes, tempo, bar signatures, tuning, key signatures, and chords. The same provider can report incomplete analysis, receive a validated nonempty subset of the factory's advertised analysis types, expose stable processing-algorithm properties, accept guarded per-source algorithm changes, observe source-content invalidation, notify the host of progress or changed results, and persist bounded source state. Licensing queries validate booleans, counted pointers, unique advertised content types, and transformation subsets. The controller also copies typed host source or musical-context content into caller-bounded storage and guarantees host reader destruction. `ara_music_analysis.Analyzer`, with `ara_tuning_analysis` retained as a compatibility name, uses fixed source, channel, frame, note, envelope, tempo-entry, bar-signature, key-signature, chord, and name storage. Its polyphonic path applies overlapping Hann windows, semitone spectral candidate selection, sub-semitone frequency refinement, fixed maximum polyphony, gap-tolerant tracking, perceptual volume scaling, and checked note durations. It analyzes channels independently and merges overlapping same-pitch events, then sorts and transactionally publishes official note content. It estimates monophonic equal-temperament concert pitch from a leading window and streams longer source ranges into per-channel RMS and positive-onset envelopes. Overlapping local windows establish beat phase and tempo, prefer the shortest strong autocorrelation lag, stabilize octave relationships between adjacent windows, and integrate continuous quarter positions for constant or piecewise variable material. A whole-source estimate is only a fallback when no local window succeeds. Meter analysis maps onset accents through that tempo map, distinguishes simple, odd, and compound templates, selects downbeat phase, and confirms whole-bar-aligned changes. Key analysis maps detected notes through the tempo map, accumulates duration and volume weighted pitch classes in bounded windows, correlates every major and natural-minor profile, rejects weak or ambiguous evidence, and confirms sustained changes. Chord analysis filters short note artifacts, scores triad, suspended, sixth, seventh, added-tone, extended, and power-chord templates, retains the lowest active pitch as the inversion bass, publishes sustained changes, and marks sustained gaps with undefined-chord events. It offers general and low-register host-selectable algorithms, publishes detected notes, static tuning, bounded multi-point tempo maps, bar-signature, key-signature, and chord maps, supports an approved tuning override, and independently invalidates note, timing, tuning, and harmonic scopes while retaining the selected algorithm. Its version-8 records persist algorithm choice, tuning grade, concert pitch, copied name, tempo grade and points, note grade, and every validated note, bar-signature, key-signature, and chord field. Restore accepts versions 1 through 7, converts version-3 phase and period records into two-point maps, and stages every mapped record before replacing selected source state, so malformed or truncated data leaves the prior state unchanged. Controller archives use a bounded version-2 encoding, accept version-1 archives, resolve full or filtered persistent-ID mappings, and bound opaque provider data with `archive_extension_bytes`. `ara_extension.Extension` owns bounded playback and editor assignments, copied editor-view state, retained callback errors, and revisioned publication. `ara_source_cache.Cache` fills a complete bounded source from a non-realtime ARA reader into an inactive reference-counted generation. `ara_source_cache.PagedCache` instead owns a bounded LRU working set. It fills inactive immutable pages, commits every page, then publishes one reference-counted directory containing the exact page generations. A realtime read that races publication therefore sees a complete old directory, a complete new directory, or a checked miss that causes whole-block silence. Failed fills leave the prior directory active. Render readers pin immutable directory and page generations and perform only bounded atomics and copies. `ara_content_fades.Analyzer` reads bounded head and tail windows on the model thread, selects the finite channel with the greatest AC energy, derives zero-crossing fade durations, and publishes only exact render-description matches. `ara_tempo_warp.Builder` validates source and context tempo maps, merges their sync boundaries into piecewise playback-to-modification warps, verifies endpoint compatibility, and publishes only exact model revisions and descriptions. `ara_playback_renderer.Renderer` resolves assignments into immutable realtime snapshots and reads through either cache or another product-supplied realtime source provider, never through the potentially blocking ARA host readers. It uses fixed scratch storage, applies binary-searched tempo warps or ordinary time mapping, supports linear, Catmull-Rom cubic, or normalized eight-tap windowed-sinc interpolation, applies analyzed linear, smoothstep, or equal-power head and tail fades, sums overlaps, and publishes deterministic silence when its provider reports unavailable data. `SimpleEffect` and `HighLevelEffect` initialize, bind, unbind, and release its stable-address state while aggregating both ARA entry points into the canonical audio component identity. `ara_registration` supplies matching main-factory class metadata and compile-time product class-list assembly. `examples/ara_playback_plugin.zig` composes these pieces into a validated dual-precision stereo product whose VST3 audio callback follows project sample time. Its factory-created controllers own the music analyzer and 32,768-byte archive-extension budget. One canonical f64 paged cache, content-fade analyzer, tempo-warp builder, and windowed-sinc renderer feed f64 output directly and f32 output through bounded fixed scratch conversion. Spectral stretch algorithms, external-host fixtures, and real-host validation remain open.

The toolkit-neutral `gui.Editor`, `gui.Context`, and `gui.Adapter` contracts live in `zig-vst3-plugin-core` beside the processor runtime. `lv2.ui.Adapter` binds those contracts to the LV2 UI ABI. It owns one editor instance, attaches it to the host parent, translates plain control-port values and normalized edits, forwards optional touch and resize calls, and exposes idle, host resize, show, and hide interfaces. A toolkit backend supplies construction and the native child widget. The optional `vstgui_lv2_backend` builds parameter-driven sliders, toggles, and menus from reflected metadata, returns VSTGUI's platform widget, forwards gestures and resize requests, and rolls failed attachment back completely. The full `zig-vst3-plugin` package preserves its existing `gui` and `lv2` aliases. Both processor and editor contracts can therefore be consumed without importing VST3.

`Vst3Effect` derives main and auxiliary topology, event buses, host-transport requirements, parameter metadata, and the checked processor adapter from one high-level plugin declaration. `Vst3Controller` derives the matching ordinary reflected controller. Variants accept configured parameter descriptors and build the processor and controller parameter sets from that same value. The older `SimpleEffect` processor contract remains available for direct ABI and conformance integrations. Mono Gain, Surround Gain, Sidechain Ducker, Auxiliary Output Splitter, Event Echo, Fixed Rate Processor, Resource Swap, IR Loader, Sample Player, Channel Strip, Parametric EQ, Resonant Filter, Model Shell, and C Kernel Probe exercise the VST3 runtime adapter across ordinary, immersive, auxiliary-input, multi-output, output-event, component-state, host-request, background publication, decoded-audio import, scalar, graph, and text telemetry, editor activity, specialized-controller, and native-kernel paths. IR Loader keeps its bounded convolution engine in heap-owned stable storage while the checked runtime owns activation, processing, and teardown. Resource Swap uses the same ownership pattern for a worker request that captures a pointer to its internal publication exchange. The engine reaches its final address before the request is submitted, and teardown joins the worker before freeing that address. Model Shell extends that pattern to persistent resource recovery, preparation-sensitive latency approval, bounded component state, and controller-facing scalar and text telemetry. Sample Player combines decoded-audio transfer, MIDI events, sample-accurate parameter latches, playhead graph publication, and editor activity through one high-level processor. Channel Strip keeps its specialized controller and importer while its processor publishes two graphs and three scalar meters through the adapter. Parametric EQ and Resonant Filter keep controller-driven response curves separate from activity-gated processor spectrum graphs while both processing precisions use typed parameter views. The Mono Gain LV2 bundle exercises dynamic loading, audio, control, typed and raw Atom MIDI, arbitrary non-MIDI Atom bodies, sample-offset time Position input, block-length option queries and inactive reconfiguration, latency, activation cycles, URID mapping, parameter-state round-tripping, declaration-driven port metadata, two generated factory presets, and a separately linked VSTGUI parameter UI. Dynamic smoke coverage checks both descriptor symbols, UI metadata, required parent handling, widget publication, and teardown. The Mono Gain AUv2 reference exercises an owning component factory, registered bundle metadata, dynamic loading, input pull, immediate and ramped sample-accurate automation, Core Foundation class-info state, rendering, and teardown. External AU hosts, dynamic topology, remaining LV2 extensions, and advanced custom-component bindings remain open. Adding AUv3 or AAX wrappers remains open architecture work. Cocoa, Win32, and runtime-loaded X11 and Wayland top-level window backends are implemented but still need physical lifecycle, display-scale, input, accessibility, and visual validation. The Wayland module embeds the stable xdg-shell protocol metadata it uses and dynamically resolves libwayland-client, so ordinary plugins gain neither development-header requirements nor Wayland linkage. `vst_wayland_standalone_frame.StandaloneBridge` presents the backend as one ref-counted `IPlugFrame`, `IWaylandFrame`, and `IWaylandHost` identity while delegating `IRunLoop`, validating native object access, negotiating child resize, and tracking connection borrows through teardown. The bounded standalone Steinberg run-loop driver polls the file descriptors and timers registered by both Linux VSTGUI paths. Physical VSTGUI integration remains unconfirmed. Complete timestamped UMP device and block-scheduling contracts are implemented. WinMM and ALSA MIDI 1 and UMP RawMIDI use fixed-capacity native timestamp queues for future output, stable equal-time ordering, cancellation, and retained output failures. Linux UMP connects through runtime-loaded current ALSA control and UMP APIs. The optional Windows UMP backend connects through the Windows MIDI Services App SDK, uses endpoint device IDs for persistence, and accesses complete packets through the raw connection extension. Its SDK is an isolated build-time dependency. Ordinary plugins and the MIDI 1 backend do not acquire it. Linux standalone audio can use either runtime-loaded ALSA PCM or the separately imported PipeWire module. PipeWire enumerates bounded graph-node snapshots, resolves stable directional selections, negotiates planar f32 or f64 streams, and exposes combined or independent callbacks without affecting ordinary plugin binaries.
