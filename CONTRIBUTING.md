# Contributing

Keep changes small, focused, and covered by the validation tier that matches the risk of the change. `docs/roadmap.md` tracks current project priorities, and `docs/layer1-release.md` tracks the raw-layer release gate.

For each code change:

1. Read the nearby code and relevant docs before editing.
2. Keep the change scoped to one coherent behavior or documentation update.
3. Run the relevant local checks.
4. Include the relevant test output in the PR.

Do not add TODO or FIXME markers unless they reference a tracked issue.
